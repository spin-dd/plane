## 置換しなかったもの

### 用語

| 語                                | 理由                                                         |
| --------------------------------- | ------------------------------------------------------------ |
| エピック                          | 建設側に安定した対応語が無い。運用が固まってから判断する     |
| ページ / ビュー / ラベル / 担当者 | 建設業でもそのまま通じる                                     |
| ワークスペース                    | 会社を指す。現場（プロジェクト）の上位概念として機能している |

### ファイル

`ja/integration.json` は **プロジェクト→現場 の対象外**。
GitHub / GitLab / Slack 側の project を指す文が混在しており、
「GitHubリポジトリをPlane現場にマッピングします」のような不自然な文になるため。
同ファイルでも 作業項目→課題 / サイクル→工程 / モジュール→工種 は適用している。

### ブランドマーク（DNT）

翻訳規約上は翻訳禁止だが、**日本語のまま維持している**箇所がある。

| 語       | ja の現状  | 件数 |
| -------- | ---------- | ---: |
| Stickies | 付箋       |   45 |
| Intake   | インテーク |   15 |
| Plane AI | AIチャット |    3 |
| Galileo  | ガリレオ   |    2 |

これらは upstream の翻訳が DNT に違反している状態だが、**現場ユーザーの可読性を優先して
fork では変更しない**という判断（2026-08-09）。こちらが手を入れない分、追従時の
コンフリクトも発生しない。upstream のブランド方針は upstream の判断に委ねる。

## 追加・変更するときの手順

1. 置換対象の語が一般名詞として別の意味で使われていないか、`ja/*.json` 全体で前後の文脈を確認する
   （例: `ライフサイクル` `リリースサイクル` のような複合語が無いこと）
2. 置換後に `pnpm --filter @plane/i18n run sync:check` を通す（19 ロケール 100% であること）
3. この表を同じ PR で更新する
4. 長文が不自然になっていないか、40 文字以上の文字列を無作為抽出して目視する
